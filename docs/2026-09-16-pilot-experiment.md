# 一场日语直播回放的切片实验方案

> 总体执行计划已整合为[主计划](superpowers/plans/2026-09-16-kurocut-master-plan.md)。后续从主计划开始；本文保留为专项参考，涉及本地/云端优先级与阶段顺序时以主计划为准。

适用条件：Windows、RTX 5080、32GB 内存；你负责成片观感，懂日语的朋友负责语言和语境。尚未选定原始直播录像；已收到的 Shorts 仅为成片质量范本，以下是实验协议，不是实验结果。

## 实验要回答的三个问题

1. 给定一段正确素材，机器能否自动做出接近目标视觉风格的短片？
2. 不给时间戳，机器能否从整场直播中找到值得剪的内容？
3. 把朋友审稿、你的修改和拒稿都算上，每条片是否仍有利润？

三项分开验收。输出 MP4 只能证明渲染成功，不能证明选段精彩、日语正确或客户愿意付款。

## 1. 选素材与冻结输入

第一场选 1–3 小时、单人日语直播，优先《鸣潮》，带清楚的主播人声和固定位置的 VTuber。需要包含对话、游戏情境和明显反应；不要以全程刷本、几乎无言语或大量多人重叠说话作为第一次实验。

使用有权处理的原始回放，建议 1080p；参考 Shorts 仅作风格对照，不能替代长直播测试输入。有多个音轨时先试听确认主播人声所在轨道。

记录文件名、来源、时长、分辨率、音轨、文件 SHA256。把同一场记作 A 场；调试后另外选同主播、同类游戏但内容不同的一场作为 B 场。不要通过重新编码 A 场充当 B 场。

## 2. 朋友独立做参考标注

AI 首次运行之前，朋友浏览 A 场，标 3–5 个“自己愿意剪成短视频”的时刻。保存到独立表格或文本，**不提供给 AI 选段程序**。

| 字段 | 填写内容 |
| --- | --- |
| 起止时间 | 原片分钟:秒，不是成片时间 |
| 必要铺垫 | 不保留哪句话/哪段画面，观众就看不懂 |
| 关键时刻 | 事件、反转、好笑的台词或操作 |
| 主播反应 | 反应开始与结束，笑声是否值得保留 |
| 风险 | 人名、游戏专有词、反话、听不清、画面才看得懂的梗 |
| 中文说明 | 为什么这一段值得剪 |

这 3–5 个点不是唯一正确答案。AI 找到其他好片段可以额外通过，不能因为不在表格里就判错。朋友找参考点所花的时间记为“实验标注成本”；日常审片时间另记，避免混淆。

## 3. 实验 A1：不考选段，先验证能出片

朋友从参考点中选一个连续区间，约 45–75 秒，把它交给程序。此阶段只检验转录、字幕和成片，**不能把该结果计入自动找高光能力**。

要求自动产出：

- 日语原声、日语字幕的 1080×1920 MP4。
- 日语 SRT/ASS；中文审片说明独立保存。
- 上下分区主布局；如果这段确有反应，增加人物放大；圆窗可以在模板阶段补齐。
- 对应的原片时间与处理日志。

朋友听原声并核对日语；你在手机大小预览下检查字幕是否太小、遮挡主体、切掉铺垫，以及是否有突兀的音频断点。只修实际问题，不先堆特效。

**通过标准：** 一条片可完整播放，字幕没有关键语义/人名/否定错误，开头和结尾完整，游戏事件与人物反应都看得到。样例有大量精细装饰时，把“基础交付”和“装饰还原”分别记录，不能以基础通过宣称完全复刻。

用户明确要求 AI 按内容、语气和画面自动编排；参考片仅是质量范本。基础出片之后，先做 **8 秒动效能力小样**，再把它接入多模态编排器。小样验证浮动字幕、圆窗移动、局部黑白与贴纸等组件，不要求每条片都出现这些效果。检查转场是否造成音频重叠、字幕错位或时长变化。具体观察见 [动效拆解](2026-09-16-reference-motion-analysis.md)。

增加 A1b：分别选择反差笑点、精彩操作/紧张段落、平静聊天三类真实素材，自动判断铺垫、事件与反应并生成编辑表。同一段做固定版式和 AI 自适应版，隐藏版本标签后由你和朋友比较叙事完整性、强调是否合适、画面遮挡、特效滥用和修改分钟数。固定片段对比检验编排能力，不算全场选段通过。正确的简单剪辑可以优于强加动效。

## 4. 实验 A2：整场盲选

冻结当前模型、提示词、采样策略和可用编辑组件；只给程序 A 场原片，不给朋友的参考表或 A1 时间戳。程序从全场自行处理：

```text
全场转录＋全场音视频低成本分窗观察 → 合并候选
→ 候选带原声精看 → 定位铺垫/事件/反应 → 自动编辑决策
→ 最多10条候选说明 → 排名前3条完整草稿成片
```

候选须给出原片起止、日语证据、中文说明和不确定项。允许返回不足 10 条甚至零条；没内容时不强行凑片。

先保存首次结果，再让朋友和你审核。每条标记：可直接采用 / 小改可用 / 需大改 / 不值得剪。冻结结果后才对照隐藏的参考表。

| 指标 | 计算或记录方式 | 首轮目标（项目门槛，非行业标准） |
| --- | --- | --- |
| 候选可用性 | 直接采用＋小改可用 / 实际输出数 | Top 10 至少3条可用；同时保留真实分母 |
| 预标高光命中 | 参考高光被候选充分覆盖的数量 / 参考数 | 先记录；人工3个参考点时争取至少命中2个 |
| 语义质量 | 看完实际导出的每一条，记录重大错误 | 最终交付前重大错误清零 |
| 字幕初稿错误 | 随机抽100句，不足全量；按关键/普通分开 | 记录修正量，决定哪种模型省审核时间 |
| 时间对齐 | 抽查20句字幕起点 | 至少18句误差≤300ms |
| 视频质量 | 字幕、主体、铺垫、包袱、音画同步、编辑适配与特效滥用 | 至少3条不同情境人工通过；不够则如实记不够 |
| 人工成本 | 找素材、审片、修改、沟通分别计时 | 稳定后你≤45分钟/次，朋友约≤15分钟/次 |
| 机器成本 | 转录/渲染耗时、API实际费用、采样显存峰值 | 先实测，不预设5080每小时产量 |

首次盲选如果使用了 A1 同一时段，要披露该点曾参与渲染调试；禁止用 A1 的时间戳或文本当自动选段提示。最终泛化结论以 B 场为准。

## 5. 修改只针对失败原因

| 失败现象 | 优先调整 |
| --- | --- |
| 角色名、人名频繁错 | 术语表＋小样对比日语模型；朋友确认 |
| 找到反应却没铺垫 | 扩展候选前文和结尾，检查选段提示词 |
| 声音很大但无内容 | 降低音量/笑声信号权重，要求情境与结果证据 |
| 漏掉无台词的游戏笑点 | 记录为视觉召回缺口；检查全场多模态 coverage 和采样缺口，必要时局部加密，不假装文本能解决 |
| 字幕跨剪切点错位 | 修时间映射，不手工偏移每条成片 |
| 人物被切掉 | 改该主播 ROI 与布局，检测原片是否中途换版式 |
| GPU运行失败 | 核对驱动、CTranslate2版本与FP16，先60秒小样 |
| 机器很快但人工很慢 | 优先改字幕质量、审稿操作和客户交付范围 |

每次只改一类主要问题，再用相同片段对比。最多先做两轮调整；没有明确改善时暂停扩功能，把错误样本留给下一次针对性修复。

## 6. B 场独立验收

用 A 场调好的配置原样运行 B 场，不再参考 B 场人工高光改提示词。朋友另做 B 场参考标注，仍在 AI 输出冻结后揭晓。

保留首次运行结果与最终审核结果。若换一场就大量裁错或全是无聊片段，只能说“单场演示跑通”，不能说“稳定自动生产线”。

首轮共两场的结果只支持小规模试单。稳定性结论需要后续不同日期、情境的约20条交付继续验证。

## 7. 费用、分工和继续条件

你：选择业务方向、提供素材、校准版式、检查画面、记录自己的工时。朋友：独立高光参考、日语语义和梗的审核。程序：转录、音视频理解、选段、内容自适应编排、字幕、渲染、记录耗时。招聘方：是否愿意按约定价格验收，这是内部测试不能替代的最后一项。

建议 A 场试验现金预算上限 300 元，含约定的朋友审核报酬、API 和必要杂费；不含双方时间折价和现有硬件购置。该金额是预算建议，不授权本轮充值或采购。文本 API 每场先设10元上限；视频理解费用单列并按所选模型核算，不能套用文字预算。无配置、价格或允许的上传范围时只做离线结构测试。

每次尝试记录：

```text
场次 | 候选编号 | 最终时长 | 机器耗时 | API费用 | 朋友分钟/报酬
你的分钟 | 修改轮数 | 验收状态 | 报价 | 实际收款 | 拒稿原因
```

不把失败稿成本删掉。统一口径：

```text
一批稿件税前结余 = 付费条数 × 单价
                − 全部尝试的外部支出
                − 固定费用分摊
                − 你的全部人工小时 × 目标时薪
```

**建议继续投入的证据：** A1 基础片通过，A2 有可用高光，B 场没有明显退化，朋友愿意按可持续的时间/报酬参与，且客户有付费试单反馈。第一步的实际交付是“3条可审样片＋实验记录”，不是无人值守批量发布。
